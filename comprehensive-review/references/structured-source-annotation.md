# 结构化来源标注模板

**来源**: BTC Rubrics 评估一周聚合分析 · 2026-07-25 P0 改进

## 问题

BTC 交易报告连续一周的来源标注率在 40-60%，Rubrics "来源类型"维度稳定在 5-6 分，D007 连续触发。根因：LLM 习惯在底部笼统标注一行"数据来源：[一手] KuCoin API"，而非逐指标/逐引用标注。

## 模板

在报告生成 prompt 中强制执行：

```
1. **技术指标**：每个指标逐行标注来源。
   格式：`[来源: KuCoin API]` 或 `[来源: 计算自KuCoin K线]`

2. **外部引用**：ETF流量、政策动态、新闻事件——必须附带可点击 URL。
   若无 URL，标注 `[已读取但URL不可用]`

3. **统计断言**：如"反弹概率65-70%""布林挤压后≥3-5%振幅"——
   必须标注 `[推测, 基于历史回测]` 或 `[一手, 来源: XXX]`

4. **量化底线**：完整报告中至少 **3 个可点击外部 URL**。
   技术指标 100% 标注来源
```

## 效果验证

BTC 虚拟量化系统 v1.2.0（2026-07-25）：
- 改前（7/25 07:47）：来源标注覆盖率 60%，D007 触发
- 改后（7/25 20:45）：全部 11 个数据点逐行标注 `[来源: KuCoin API]`
- 预期下一次 Rubrics 评估：来源类型 5-6→7-8，D007 清零

## 适用范围

任何生成数据分析报告的 cron prompt——BTC、科创50、银行、国电、机器人。不是 BTC 专属模式。
