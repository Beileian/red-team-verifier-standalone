# Red Team Verifier Standalone

**通用输出验证代理** — 改编自 [Agile-V](https://agile-v.org/) red-team-verifier v1.4（CC BY-SA 4.0），由隐序（Yinxu）适配为通用输出幻觉审查体系。

一套四层的输出防御架构，用于拦截 LLM 幻觉、数字错误、跨实体串扰和推理缺陷。

## 它解决什么问题

**一句话**：LLM 生成的报告/代码/分析，怎么保证它没在编？这个仓库给了四道独立防线——从「输出前自检」到「独立子代理审查」再到「挑审查者毛病」。

**生活类比**：你写了一份重要报告，不放心自己的判断，于是：
1. 自己先对着清单检查一遍（gate 自检）
2. 找三个不认识的专家分别独立审（三路并行）
3. 再找个专门「挑专家毛病」的人看（Refute Pass）
4. 最后一个人把三份意见合成一份结论（合成器）

## 四层架构

```
┌─────────────────────────────────────────────────────┐
│ ① base/                     Agile-V 验证代理原版      │
│    (red-team-verifier v1.4)  代码/固件/原理图验证      │
├─────────────────────────────────────────────────────┤
│ ② local/                    隐序适配层 v1.2.0         │
│    (red-team-verifier-local) 通用输出验证 + 分级触发   │
│    P0阻塞 / P1异步 / P2跳过                           │
├─────────────────────────────────────────────────────┤
│ ③ output-integrity-gate/    输出完整性门禁 v1.18.0    │
│    主进程输出前 30 秒自检（7 项）+ 风险分级            │
├─────────────────────────────────────────────────────┤
│ ④ comprehensive-review/     全面评审框架 v1.36.0      │
│    Rubrics 八维评分 + 红蓝互辩 + 决策三角 + 理解债闸门  │
└─────────────────────────────────────────────────────┘
```

## 各层职责

| 层 | 定位 | 触发方式 | 核心能力 |
|:--:|------|------|------|
| ① base | 验证代理原版 | 代码/固件/原理图验证 | FT-CODE 故障分类、Eval Gate、多周期验证 |
| ② local | 通用输出验证适配 | gate 分级判定后 delegate_task 唤起 | 幻觉猎杀清单、FT-CODE 扩展、跨实体检查 |
| ③ gate | 输出前自检 | 任何含数字/事实的输出 | 7 项自检、风险分级（P0/P1/P2）、P0 阻塞唤子代理 |
| ④ comprehensive-review | 全面评审 | 「全面评审」「Rubrics+红蓝」触发词 | Rubrics 八维、红蓝互辩、决策三角、理解债闸门 |

## 管线顺序

```
生成方产出 ──→ ① gate 自检 ──→ ② 分级 ──→ ③ verifier 独立审查 ──→ ④ 交付
                    │                │              │
                30秒自检        P0=阻塞       子代理不共享上下文
                7项清单        P1=异步         独立验证幻觉/错误
                              P2=跳过
```

| 步骤 | 角色 | 做什么 | 产出 |
|:--:|------|------|------|
| ① | gate（自检门禁） | 主进程输出前 30 秒自查 7 项：数字范围/来源标注/实体绑定/ID 截断等 | 自检结果 + 风险等级（P0/P1/P2） |
| ② | gate 分级判定 | P0=含交易建议/财务断言 → 阻塞；P1=事实判断无交易 → 异步；P2=纯文档/行政 → 跳过 | 触发决策 |
| ③ | verifier（local 子代理） | 独立验证幻觉：7 项 FT-CODE（数据/来源/串扰/范围/逻辑/矛盾/格式），不共享主进程上下文 | 问题列表（CRITICAL/MAJOR/MINOR） |
| ④ | 合成器 / 主进程 | 汇总多路审查结果，标注降级状态，生成最终交付 | 微信推送摘要 + 完整报告 |

## 各方扮演的角色

| 方 | 角色定位 | 独立于谁 | 负责什么 |
|------|------|------|------|
| **生成方**（Build Agent） | 产出者 | — | 写分析报告/交易建议/代码 |
| **gate** | 快餐自检 | 自己（输出前自查） | 抓显性错误：数字超范围、来源没标、实体绑定错、ID 截断；判定 P0/P1/P2 |
| **verifier（local）** | 体检 | **不共享生成方上下文** | 抓隐性错误：推理断裂、内部矛盾、跨实体数字串扰 |
| **Refute Pass** | 审查者的审查者 | 独立于三路审查者 | 挑三路共同的推理盲区——三路都说「对」的时候，主动问「如果错，最可能因为什么」 |
| **合成器** | 汇总者 | — | 把多路审查结果合成一条推送 + 完整报告归档；校验内容类型匹配 |

## 关键设计思想

1. **正交性**：三路用不同模型（Flash 查数据 / Pro 挑毛病 / M3 看宏观）——不是三个 AI 一起对，而是让三个 AI 很难错到同一个地方
2. **独立上下文**：verifier 不看生成方的推理过程，只看最终输出——才能发现生成方自己看不见的幻觉
3. **分级触发**：P0（含交易建议）阻塞式审查，不过不交付；P1 异步后台审；P2 跳过——**不是所有输出都值得花全量审查成本**

## 安装

将对应 skill 目录复制到你的 agent 的 skills 目录：

```bash
# 通用输出验证（推荐组合：base + local + gate）
cp -r base ~/.hermes/skills/dogfood/red-team-verifier/
cp -r local ~/.hermes/skills/dogfood/red-team-verifier/local/
cp -r output-integrity-gate ~/.hermes/skills/dogfood/output-integrity-gate/

# 全面评审（可选，用于报告/方案的深度评审）
cp -r comprehensive-review ~/.hermes/skills/dogfood/comprehensive-review/
```
